# 本地定制与维护

本页说明本地 Fork 的 `main` 保留了哪些定制，以及各自在哪里维护。上游是卡兹克的原工程。Fork 的源码、各台 Mac 安装的代码快照和本机中间层分别维护，部署和验收状态见 [ROADMAP.md](../ROADMAP.md)。维护规则见 [AGENTS.md 的「本地 Fork 维护」](../AGENTS.md#本地-fork-维护)。

## Fork 源码中的定制

| 功能 | 行为和维护位置 |
| --- | --- |
| Codex 原会话续接和中文标题 | Codex 插件复用桌面的 App Server。原会话空闲后接着做，断线后读回原轮次。标题使用 `autoloop-中文模块名｜持续目标`。接单程序提供稳定请求标识和外部任务的停止控制。[插件说明](plugins.md#codex-原会话续接) · [标题说明](plugins.md#codex-会话标题) |
| 飞书卡片 | 默认沿用上游的完整正文和展开回答框，显示「项目｜事项｜状态」和卡片编号。彩票来源可以显示中文功能名。插件也保留可选的定制样式及对应文字回调。可信项目名和任务名由中台提供给通道。[展示协议](protocol.md#飞书卡片展示) · [飞书插件](../plugins/feishu/channel.ts) |
| 已发待答卡片更正 | 本人按版本更正标题与正文。更正追加到事实记录，后续回答、结案或重启仍使用新文案，并更新原消息。[更正协议](protocol.md#更正待答卡片) |
| 运维诊断和项目接入 | `doctor` 逐项检查受管的 macOS 服务。CLI 会单独提示本地权限拦截导致的连接失败。可信规则可配置 `wrapper`，在执行前准备项目并在执行后核验结果。[服务诊断](../host/service.ts) · [CLI](../cli/main.ts) · [执行包装](plugins.md#项目执行包装) |
| 每日运行摘要 | 仓库中的独立脚本通过现有接口读取状态，汇总当天轮次、待决定卡片和离线接单程序，由现有规则定时运行。[使用说明](../README.md#每日运行摘要) |

Solo to Team 集成保存在 `feature/solo-to-team-integration`，已从 `main` 撤下。

## 本机中间层

在 chezmoi 的 `dot_local/share/agent-autoloop/` 维护共享宿主和本地通道包装。共享宿主合并各项目的规则片段，独立新任务默认开新会话，并复用中台现有接口收尾一次性任务。Codex 双端问答的卡片展示及失败后的回答补传，也在这一层维护。

中台通过[插件加载入口](../host/plugins.ts)优先读取安装目录中的同名插件。启用本机飞书包装时，私有插件入口转调该包装，再由包装复用安装快照中的基础飞书插件。排查行为时要同时核对 Fork 源码、安装快照和本机插件入口。

## 放在哪一层的例子

- 彩票通知的中文来源和普通聊天问答卡的排版属于本地显示偏好。通道插件可以根据可信项目身份整理展示，更新时继续沿用原卡片和消息绑定。
- 多个独立问题共用一条业务规则时，由中间层为每个问题确定稳定身份，再利用中台已有的事项划分。回答、重试与复查沿用原问题身份。实施进度见 [ROADMAP.md](../ROADMAP.md#未完成任务)。
- 复查发卡后，回答曾因定时记录被清理而丢失原业务事件编号。中台在复查到期时掌握原编号，源码修复把编号随复查事件持久保存，之后可沿事实记录追溯。这类通用修复可以单独整理给上游。[回归测试](../tests/schedule.test.ts) · [查找原事件的实现](../kernel/query.ts)
